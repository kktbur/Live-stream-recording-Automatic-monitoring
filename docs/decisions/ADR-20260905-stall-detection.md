# ADR-20260905：录制卡顿检测与安全收尾

- 状态：本地实现，待 Draft PR、远程 CI 和负责人验收
- 日期：2026-09-05
- 范围：Reco Box `0.3.0` / PR-11

## 背景

PR-10 已为录制失败预留 `Stalled` 分类，但录制管理器此前只在进程退出或磁盘保护
时收尾。流进程可能仍然存在而输出文件长期不增长，单靠 QProcess 的运行状态无法
判断录制是否继续产生有效内容。

## 决策

1. 使用录制 Session 目录内所有文件的累计字节数作为当前阶段的确定性进度信号，记录
   最近一次增长时间；不读取媒体内容、不依赖平台特定码率。
2. 从 QProcess 发出 `started` 信号后开始计时；默认启动保护门槛为 30 秒，默认无增长阈值为
   120 秒。只有进程仍处于 Running、运行时间达到保护门槛且距最近增长达到阈值时，才进入
   `RoomStatus.STALLED`；零输出场景的首次触发约为进程启动后 120 秒。
3. 卡顿触发沿用 FFmpeg 的可控收尾顺序：写入 `q`，8 秒后 terminate，额外 3 秒后
   kill。自动触发记录 `Stalled` 失败原因，但不把本 PR 的检测实现扩展为新的恢复状态机。
4. 延时 terminate/kill 回调携带原始 QProcess 作为世代校验；如果房间已经启动新的重试，
   旧收尾回调不操作新进程。自动收尾期间的进程错误保留 `STALLED`，交给 `_finished` 统一处理。
5. 自动卡顿停止复用现有 `_finished`、录制持久化和短退避重试路径；手动停止和磁盘保护
   的既有优先级保持不变。这样本轮增加可观测分类，不同时改变整体重试策略。
6. `STALLED` 被视为“进程正在安全收尾”的忙碌状态：监控器不重复启动，房间列表保留
   状态可见性，界面允许停止但禁止编辑、删除和再次立即检查。
7. 应用启动时将没有对应运行中进程的持久化 `STALLED` 标记归一化为 `OFFLINE`，保留
   最后错误文字。该启动保护只解除不可恢复的瞬态标记，不实现完整崩溃恢复。

## 后果

- 没有增长的长时间录制会获得明确的状态和失败原因，并能进入既有重试路径。
- 文件累计大小是低成本、可离线测试的信号，但不能区分所有网络、编码器缓冲和文件系统
  延迟，因此阈值保持为显式可注入参数，后续再用 Session/故障注入证据校准。
- 本轮不会为每个录制创建新的持久化 Session 模型，也不会声称完成崩溃恢复或离线确认。

## 非目标

本 ADR 不定义 `RecordingSession` 持久化模型、恢复状态机、同 Session 恢复、离线
hysteresis、崩溃恢复、平台级真实卡顿测量或压力/故障注入。

## 恢复

回退 PR-11 的状态枚举、文件增长追踪、自动收尾、UI、翻译、测试和维护文档即可恢复到
PR-10 的行为；不回退前序 TLS、调度或错误分类变更，不修改 `main`。
